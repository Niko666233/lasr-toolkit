# L.A. Street Racing 工具集 —— 修改器 · 反编译研究 · 调试补丁

> 给原版《**L.A. Street Racing**》(Invictus Games, 2006) 做的三件事：
> **① 两个 Windows GUI 修改器**（改车辆真实性能 / 改存档）—— 双击即用的单文件 exe，不联网、不读注册表；
> **② 一份可复现的反编译研究**（TUFA 容器与自研 VM 的字节级往返 + 纯 C 重建解释器）；
> **③ 一个 3 字节的补丁**，让零售版也能进开发期调试菜单。

## English summary

Three things for **L.A. Street Racing** (Invictus Games, 2006), all generated by AI and verified by a
human against the real game:

1. **Two Windows GUI editors** — vehicle data (engine torque curves, every INT/FLOAT literal in a part
   class, `configureType` string parameters, shared-package nitro/tyre values) and save games (career,
   cars, parts, race results). Single-file exe, no install, no network. Run
   `editors/gen_snapshot.py` once against your own copy to generate the plaintext class data they read.
2. **A decompilation study** — the game's custom `TUFA` container and its VM, rebuilt from scratch:
   `.class → text → .class` round-trips **byte-identically for all 2,224 classes**, the rebuilt
   `java/classes.zip` re-packs to **304/304 identical entries (whole-file md5 matches the shipped zip)**,
   and a pure-C reimplementation of the interpreter (`vm/tufa_vm.c`) reproduces the static initialisation
   of 1,058 classes / 5,403 fields with zero errors. See docs 62–68.
3. **A 3-byte patch** (`mods/debug-menu/`) that re-enables the retail build's hidden developer menus
   (give all cars/parts, edit prestige, force race result, debug console) by flipping one flag the
   shipped game never sets, plus moving the console hotkey off the Menu key onto `~`.

**No game files, assets, or decompiled output are shipped here.** Every artefact is produced locally
from *your own* installation by the scripts in `tools/` and `mods/`. MIT licensed, not affiliated with
the rights holders.

## 这是什么

游戏的车辆性能不在文本配置里，而是编译进 `vehicles\<车>\<车身>\classes.zip` 里每个零件类的
字节码方法体里（游戏自研的 TUFA 虚拟机）；抓地力、氮气容量等一批参数又在共享包
`java\classes.zip` 的基础类里。本仓库的工具就是**原地改这些数值**（只改既有字面量的 4 字节
载荷，或同长度替换字符串里的数字），不重写游戏算法：

| 工具 | 干什么 |
|---|---|
| **车辆数据修改器** | ①**曲线页**：引擎扭矩曲线（`eRPMs` 转速断点 + `eMuls` 扭矩倍率），可单点改、整条 ×系数、一次套到同族全部阶段（stock/I/II/III/IV/WB）②**全部数值页**：该类所有 INT/FLOAT 字面量，带「作用」列（4202 个方法有标注，来自源码级反编译对齐 + 逐值校验）③**字符串参数页**：`configureType` 串里的数值 —— ★质量(kg)、尾翼气动系数、挂点、损伤、悬挂④**共享包**：氮气容量/加成、轮胎 Pacejka µ、引擎默认值与涡轮开关 |
| **存档修改器** | 生涯数据（昵称/声望/胜负/AI 强度/酒吧进度/挑战赛解锁）、车辆与零件（加车删车、按中文名加零件、装车↔后备箱）、比赛记录翻胜负 |

两个工具都会在写盘前自动备份（`<文件>.bak`），并可一键恢复；界面里直接显示备份的时刻与大小。

## 反编译研究

和修改器同一套底层（TUFA 容器 + FLZD 压缩），但目标是**证明重编译产物与原版功能一致**，而不是改数值。
四条判据都带机器证据，任何一条不过就不算通过：

| 层 | 判据 | 结果 |
|---|---|---|
| 容器层 | `.class → .tasm 文本 → .class` | **2,224 / 2,224 逐字节一致** |
| 源码层 | `.class → .lasr.src → .class`（可读可改的源码形态） | **2,224 / 2,224 逐字节一致** |
| 打包层 | 用我们自己的编译器重打 `java/classes.zip` | **304 / 304 条目一致，整包 md5 与发行版相同** |
| 运行层 | 纯 C 重建的解释器 `vm/tufa_vm.c` 跑静态初始化 | **1,058 类 / 5,403 字段，0 bad；`Init.<init>` 93,159,836 步 errs=0** |

配套还有：真值对拍探针（自研解释器 vs 游戏内 VM 逐例比较）、实机只读挂接协议，以及若干实机对照结论
（快速比赛不写生涯记录、逆行 `WRONG WAY`、干净圈 `CLEAN LAP`、结算时 prestige 的重算规则等）。

## 调试菜单补丁

零售版有一套被静态开关 `java.util.Config.majomParade` 挡住的开发菜单，而这个开关在发行版里从未被置真。
补丁只改 **3 个字节**（`Config.<clinit>` 与 `Config.init()` 各一个 `false → true`，外加把控制台热键从
"右 Alt"（常量名叫 `RCDIK_RMENU`，值其实是 184）换成 `~` 键），再用游戏自己的 FLZD 例程重新打包：

```bash
pip install unicorn
python tools/make_debugmod.py --game "C:\Games\LASR" --out classes_debugmod.zip
```

打上后：车库多出 Cheat 1/2、Increase/Decrease rank、Win/Lose BastardRace；赛中 ESC 菜单多出 win/loose；
任意界面按 `~` 开控制台（`pop intro` / `pop outro` / `champ`）。
细节、验证数据与回滚方式见 [`mods/debug-menu/README.md`](mods/debug-menu/README.md)；
这套机制的全貌（含排行榜里 3 个点选作弊码、赛中组合键、以及"风评"到底由哪几个变量驱动）
写在 [`docs/68_CHEATS_AND_DEBUG.md`](docs/68_CHEATS_AND_DEBUG.md)。

## 快速开始

需要 64 位 Python 3.11+（含 `tkinter`，官方安装包自带）。

```bash
# 1) 依赖（unicorn 用来跑游戏自己的 FLZD 压缩/解压例程，capstone 用于反汇编）
pip install unicorn capstone
pip install pyinstaller        # 仅当你想自己打包 exe

# 2) 从你自己的游戏目录生成工具所需的明文快照（只需一次，几秒钟）
python editors/gen_snapshot.py

# 3) 直接运行
python editors/vehicle_editor.pyw
python editors/save_editor.pyw

# 4) 打包成单文件 exe（产物在 editors/dist/）
python editors/build_exe.py
```

游戏目录默认 `C:\Games\LASR`，可在界面顶部改。工具自检：

```bash
python editors/selftest_core.py                        # 压缩/解压往返 + 原地改字面量
python editors/smoke_vehicle_editor.py                 # 车辆工具（无头跑真实 GUI 流程）
python editors/smoke_save_editor.py                    # 存档工具
python editors/smoke_cfg_and_shared.py                 # 字符串参数页 + 共享包
python editors/smoke_no_unicorn.py                     # 封掉 unicorn 跑一遍（= exe 环境）
python editors/check_label_table.py                    # 「作用」列标注表复核
```

详细用法见 [`editors/README.md`](editors/README.md)。

## 「作用」列与命名是怎么来的

不是猜的：`gen_literal_labels.py` 从源码级反编译结果里抓「每个字面量在源码里绑到的
字段/数组名」，再逐方法用字节码校验（个数与取值都要对上），覆盖 4221 个方法里的 4202 个
（99.5%）；构造器那 894 条是用字节码的结构性证明 + 跨车体一致性预测补出来的，值对不上就
整条丢弃（宁可不写）。共享包的关键位置是逐字节核对后手写标注。

## 已知边界（未验证的部分）

- 明文写入（`原样 TUFA`）在**车辆包**上已实机验证被游戏接受；在**共享包 `java\classes.zip`**
  上**尚未**实机验证 —— 那里是核心类（含 `IVehicle`），改坏可能连游戏都起不来，务必先备份。
- 共享包在打包 exe 里只能用明文写（模拟器在冻结产物里会崩），源码模式（`.bat`）可以用游戏
  自己的 FLZD 原格式重打包，更稳。
- 个别类的反编译结果与安装包不同步（例如 `Hatch_Trend_IEngine_stock`），这类位置的标注不可信，
  但**数值永远从字节码读取**，所以只影响显示。
- 零件自带的气动点（`wing`）是否真的并进整车气动，尚未实机对照确认。
- 反编译研究里 202 个只读引擎状态的 native 函数没有逐条实现（沙箱返回 0 与原版在沙箱里等价），
  整局逐帧的渲染/物理等价只能实机目视 —— 这两块在 `docs/65` 里标为**边界**而非缺口。
